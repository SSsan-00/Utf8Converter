# Utf8Converter

元ファイルを守り、文字の内容を変えず、安全にUTF-8へ変換するWindows向けCLIです。
指定フォルダを再帰的に処理し、隣の `<フォルダ名>_utf8` にプロジェクト全体をコピーします。
ビルドの成功やアプリケーションの動作は保証範囲に含みません。

## 導入

Gitと.NET 9 SDKをインストールした環境で実行してください。
ランタイムは同梱しません。生成物を別の環境へ移す場合は、publishフォルダ全体と.NET 9ランタイムが必要です。

```powershell
dotnet test -c Release
dotnet publish src/Utf8Converter/Utf8Converter.csproj -c Release --self-contained false -o ./publish
```

上記はソースコードのルートフォルダで実行します。

更新時は `git pull` のあと、再度テストとpublishを実行します。
SDKは `global.json` で.NET 9系を使用します。

## 対象と判定

変換候補は `.cs`、`.cshtml`、`.js`、`.css`、`.html`。大文字・小文字は区別しません。
`.cshtml.cs` も `.cs` として対象です。
Shift-JISはWindowsのCP932として扱います。

| 入力 | 処理 |
| --- | --- |
| 正常なBOM付きUTF-8 | BOMも含めてそのままコピー |
| UTF-8だけで成立 | そのままコピー |
| UTF-8とCP932で成立し、文字列も完全一致 | そのままコピー（ASCII・空ファイルを含む） |
| CP932だけで成立 | UTF-8（BOMなし）へ変換 |
| 両方で成立し、文字列が異なる | 元のバイト列をコピーし、未解決として記録 |
| 不正なバイト列・UTF-16/UTF-32のBOM | 元のバイト列をコピーし、未解決として記録 |
| 対象外の拡張子 | バイト列をそのままコピー |

`.git`、`.vs`、`bin`、`obj`、`node_modules` 配下は拡張子に関係なくそのままコピーします。
JSONや設定ファイル、画像なども変換しません。拡張子による対象選択であり、汎用のバイナリ自動判定は行いません。

## 安全性

- 入力は読み取り専用で開き、書き換えません。
- ファイル全体を厳密にデコードし、不正な文字の置き換えを許しません。
- 変換出力をUTF-8で読み直し、入力をCP932で読んだ文字列と完全比較します。
- 改行コード、末尾の改行、空白、Unicodeの文字列を正規化しません。
- そのままコピーするファイルも、入力と出力をバイト単位で比較します。
- 検証に失敗した出力ファイルは削除します。
- 出力先・未完了マーカーが既に存在する場合は停止します。既存ファイルを上書きしません。
- ファイル名、階層、空フォルダ、ファイルの最終更新日時を保持します。
- シンボリックリンク・ジャンクションは追跡もコピーもせず、問題として記録します。入力パスとその親にあるリンクも拒否します。

**自動判定で元の意図まで保証することはできません。** 特にBOMのないUTF-8でも、CP932で別の文字列として成立する場合があります。
曖昧なファイルを推測で変換する機能や、文字コードを強制するオプションは設けていません。
ログを確認し、元の文字コードが確認できたファイルは別途エディタなどで対応してください。
既に文字化けした内容の復元は行いません。

処理中は入力プロジェクトを編集・ビルドしないでください。
Windowsでは入力ファイルを開いている間の書き込み・削除を防ぎ、処理前後でサイズと更新日時も確認します。
フォルダ全体の同時点スナップショットではなく、集計後に追加されたファイルや、処理していない時間帯の変更を完全には検出できません。
ACL、所有者、ファイル属性、代替データストリーム、フォルダの更新日時などの完全複製は対象外です。

## 進捗・ログ・終了コード

最初にファイル件数と容量を集計します。その後、処理済み件数・割合・入力バイト数・現在のパスを最大毎秒4回表示します。
バイト数は処理を終えたファイルの入力サイズで、書き込み・照合の実際のI/O量ではありません。
最後に変換・コピー・問題の件数と経過秒を表示します。未解決のままコピーしたファイルはコピー件数と問題件数の両方に含みます。

出力フォルダと同じ親に以下を作成します。入力ファイルとの名前衝突を避けるため、出力フォルダ内にはログを置きません。

- `<名前>_utf8.<一意なID>.jsonl`：開始、各ファイルの判定・処理・検証結果、エラー、最終集計。ファイル本文は記録しません。
- `<名前>_utf8.incomplete`：未完了マーカー。問題なく全件終了した場合だけ削除します。

エラーがあっても処理可能なファイルは続けます。読み取り失敗やリンクなどは出力に含まれないため、マーカーが残った出力は完成したコピーとして使用しないでください。
ログの最終集計が `success` で、未完了マーカーがないことを確認してください。
Ctrl+Cで中断できます。再実行する場合は、未完了の出力とマーカーを確認して別の場所へ移すか削除してください。自動再開は行いません。

| 終了コード | 意味 |
| --- | --- |
| `0` | 全件成功（`--help`も含む） |
| `1` | 未解決・コピー失敗・検証失敗・中断・I/O失敗 |
| `2` | 引数不正・入力なし・出力先既存など |

PowerShellでは実行直後の `$LASTEXITCODE` で確認できます。

## 開発・検証

```powershell
dotnet test -c Release
powershell -NoProfile -File tools/Measure-Performance.ps1
```

MSTestでCP932拡張文字、BOM、曖昧・不正な入力、改行・空白、読み込み境界、原本保持、上書き防止、中断、ロック、ジャンクション、3,000ファイルの処理を検証します。

性能測定スクリプトは一時フォルダに5,000ファイルと大きなファイルを作り、Release版CLIの経過時間とピークワーキングセットを表示します。
入力生成とpublishの時間は計測に含みません。検証後の一時フォルダは調査用に残すため、表示された場所を確認して削除してください。
実際の速度はストレージ、ウイルス対策、ファイル容量によって変わります。
処理は逐次実行し、内容を一定サイズずつ読み込みます。メモリにはファイル一覧を保持しますが、全ファイルの本文は保持しません。

初回のWindowsローカル計測では、5,002ファイル・51,931,648バイト（約49.5MiB）を7.99秒、ピークワーキングセット43.5MiBで処理しました。
内訳はCP932の小さいファイル5,000件、16MiBのCP932ファイル、32MiBのバイナリです。5,001件を変換、1件をコピーし、問題は0件でした。
これは合成データによる参考値で、実プロジェクトの所要時間を保証するものではありません。
